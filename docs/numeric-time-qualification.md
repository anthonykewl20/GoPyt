# Numeric, monetary and time qualification

This report maps the unchanged acceptance/evidence criteria of architecture
issue #17 to the implemented language domains and retained validation. Issue #17
records the final merged source and supported-platform CI decision. The evidence
below qualifies the stated bounded APIs; it is not a universal correctness,
security audit or production performance claim.

| Criterion | Implementation and direct evidence | Limits |
| --- | --- | --- |
| A1: Supported numeric operations, conversions, overflow and nonfinite behavior without silent coercion | [Spec S20](spec.md#s20--numbers-and-traps), [implementer values](implementer.md#1-values-and-equality), explicit `core.int` conversions, [finite binary64 amendment](finite-f64-amendment-2026-09-10.md). The checker rejects overflowing literals; bytecode and VM boundaries reject nonfinite values. [Generated integer programs](../gopyt/test_generated_programs.py), [all-width conversion endpoints and implicit-conversion rejection](../gopyt/test_numeric_conversions.py), VM overflow/division/remainder tests, and [finite boundary evidence](../validation/finite-f64/README.md) exercise the defined behavior. | Only i64 supports the existing arithmetic/ordering operators. f64 is finite storage/pass-through; rounding and underflow are explicitly allowed. No implicit monetary/temporal unit or float conversion. Host embedding still requires correctly typed values and lifetime roots. |
| A2: Exact decimal/fixed-point monetary design with scale, rounding and currency | [Money amendment](money-amendment-2026-09-10.md), [integer implementation](../gopyt/money.py), [compiled Decimal-oracle tests](../gopyt/test_money.py), [retained money qualification](../validation/money/README.md). | i64 coefficient, scale 0..18, caller-assigned three-letter currency, bounded decimal text. Explicit rounding and mismatches; no exchange-rate, accounting, payment or registry policy is inferred. |
| A3: Timestamps, durations, wall versus monotonic time, precision and serialization | [Time amendment](time-amendment-2026-09-10.md), [runtime](../gopyt/temporal.py), [compiled time tests](../gopyt/test_temporal.py), [retained time qualification](../validation/time/README.md). | i64 nanoseconds; explicit-offset timestamp profile; no implicit precision loss. POSIX excludes leap seconds, and the parser rejects them. Origin IDs separate VM clock samples but are not authentication. Host resolution, suspend and scheduling limits remain. |
| A4: Independent arithmetic oracles and real data containing negatives, precision boundaries, rounding and clock anomalies | Integer big-number expectations, exact Decimal constructions/raw f64 bits, Decimal money oracle, Fraction date oracle and OS calendar oracle. All 541,909 UCI price/quantity rows and date rows pass their respective frozen policies. Real negative quantities/prices and precision/rounding cells are retained; [IERS Bulletin C 52 marker replay](../validation/time/iers-leap-replay.json) checks the real UTC leap discontinuity. Clock rollback, backwards samples, mixed origins, clock failure and cancellation are separately injected in compiled tests. | UCI supplies no historical timezone and no backwards adjacent date samples. Fixed UTC is a disclosed test interpretation. IERS markers are real source data; clock-fault injection is synthetic, not a field incident. The leap marker is deliberately rejected, not silently converted. |
| E1: Reviewed design, implementation, regressions/end-to-end tests and failures | The three normative amendments, source-linked tests and `validation/finite-f64`, `validation/money`, `validation/time` retain decisions and observations. The initial float-infinity reproduction, generated-lock setup failure and unpinned retail-cache failure remain available alongside passing reruns. | Review here is repository implementation review, not the independent security audit required by #26. |
| E2: Frozen workload/source identities, independent oracle, limits and unsuccessful trials | Each real-data probe validates a preapproved workbook hash, records its runtime/tool hashes and acceptance conditions, and verifies unchanged identities before passing. Exact transformation/rounding policies and all-row counts are retained. Wheel reports record source/build identities. | Reported durations identify trials; no throughput target or production performance qualification is claimed. Failed probes are retained, with the actual corrections disclosed. No dataset is substituted for full-corpus verification. |
| E3: User documentation and architecture tracker with bounded claims | The amendments, current stdlib declarations, implementer links, this report and the updated architecture programme describe final behavior. The issue tracks merge/CI outcomes separately. | Finite tests support these acceptance cases, not universal correctness or security. Remaining architecture issues retain their own acceptance gates. |

The local full regression suite passes 795 tests on Python 3.14.7. Focused numeric,
money and time cases also run on Python 3.11.16. Guard calibration, stdlib parity,
contracts, reproducible wheels and installed upgrade/rollback pass; reports are
linked above. Linux/macOS and both supported Python versions are independently
required by PR CI before the issue is closed.
