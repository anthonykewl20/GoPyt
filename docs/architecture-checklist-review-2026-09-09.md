# Architecture checklist review: 2026-09-09

All **193 original checkboxes** were reviewed: 97 acceptance criteria and 72
evidence requirements across issues #3 through #26, plus the 24 entries in
[tracker #2](https://github.com/anthonykewl20/GoPyt/issues/2).
The [milestone](https://github.com/anthonykewl20/GoPyt/milestone/1) remains open.
**None of the 24 architectural issues is fully qualified.** Three individual
criteria are already supported: #7 A1 (batch isolation/ABA specification), #7 A3
(documented bounded idempotency/retry patterns), and #25 A2 (honest data accounting
and independent exact-result oracles). The remaining criteria stay unchecked.

The reviewed baseline is merged main commit
[`e2537c1362a5f3a350c456b5bf5303eb40395191`](https://github.com/anthonykewl20/GoPyt/commit/e2537c1362a5f3a350c456b5bf5303eb40395191).
PR #1 is merged; its implementation tree equals this merge tree. Earlier tracker
wording that described an unmerged draft branch was stale. Source references
below pin this commit. This review adds documentation and reproducible review
tools/evidence; it does not fix the three runtime defects below.

The scope is the architectural checklist for the language, runtime, Guard and
developer tools. Model training is excluded. This is a source-grounded engineering
review, not an independent security audit or a proof that every program, attack,
platform and failure interleaving has been tested. A missing implementation is
identified from its relevant closed interface or execution path, not from a lone
keyword search. External deployment decisions are explicitly left undecided.

Additional observations are deliberately classified separately:

- A 400-digit decimal float literal ending in `.0` compiles to positive infinity.
  f64 arithmetic/equality are already restricted. The remaining gap is an explicit
  non-finite literal/storage policy, not a claim that all numeric semantics are absent.
- A 10 ms cancellation deadline around a 250 ms blocking sleep was delivered after
  about 250 ms. This verifies the documented cooperative native boundary; it is
  not a hard end-to-end deadline.
- An old authenticated snapshot is accepted after replacing newer ciphertext;
  value-CAS also accepts a stale `A` after an `A -> B -> A` sequence. Both limitations
  are documented. Encryption integrity is not rollback protection or versioned CAS.
- A fresh process successfully read a rekeyed fixture after the old key was retired.
  This is a positive maintenance control, not online mixed-writer rotation qualification.

## Checklist corrections and work ordering

- Existing features receive credit: tracing/embedding roots, atomic batches,
  namespace policies, keyring/rekey, structured joins, HTTP shutdown, i64 rules,
  lock/version/native validation, internal Guard helper closure, source-bound
  project receipts, obligation evidence binding, and bounded telemetry.
- Unsupported extensions stay explicit: stateful Guard, native machine-code
  execution, typed persistence schemas/migrations, general foreign lifetimes,
  streaming/mapped queries, user identity, rollback anchors and semantic LSP operations.
- Priority and dependency links were planning choices, not properties proved by
  source. Their issue sections now say **proposed sequencing**. Work may proceed
  independently where the implementation permits it; no code-enforced prerequisites
  were found that justify treating every linked issue as a hard blocker.
- #26 must not automatically make experimental GPU/IPC, a native backend or every
  editor feature mandatory for every backend deployment. Keep those architectural
  tasks tracked, but decide required release scope explicitly in #3 and record any
  deferrals and resulting limits. No task is silently removed by this review.
- The existing 64 MiB snapshot is a measured scope limit, not proof that every
  production backend requires a replacement. Its suitability depends on the frozen
  workload. Likewise, monetary types and rollback anchors require explicit domain
  and threat-model decisions.

Suggested immediate order, based on the reproduced code findings: repair R1/R2/R3
with regression tests; choose the initial deployment/SLO/threat-model envelope in
#3; then qualify identity, gateway, cancellation and storage behavior for that
envelope. This is an engineering recommendation, not a dependency discovered in code.
